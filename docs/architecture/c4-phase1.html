Decisions

D1 · Real paths, prerendered at build

React Router 7 in framework mode with ssr: false and a prerender list built from the content DB. The output is still static files, so Nginx and the deploy workflow barely change.

Why: the site exists to be found and shared. Static files at real paths also work on GitHub Pages, so test and production behave the same. Astro would also work, but it would mean rewriting every page instead of moving them.

D6 · Test on GitHub Pages, release to the VPS by hand

Every push to main deploys to GitHub Pages automatically, as it already does, with a noindex tag added. The "Deploy to VPS" workflow stops running on push and gets only its "Run workflow" button. You release by opening GitHub → Actions → Deploy to VPS → Run workflow. docs/RELEASING.md explains each step in plain words.

Why: one button is the simplest safe release, and the workflow file shows every step it runs, so you can learn from it. Tags and approval rules can come later, once this feels routine.

D7 · Vietnamese at /, English at /en/

Same page structure and slugs in both languages, with hreflang links between them. Interface text lives in src/i18n; tour and service text gets an English version in the content DB. A page without an English version yet falls back to Vietnamese with a note. English text is translated from the Vietnamese by Codex (gpt-6-luna, high effort) into reviewable files, which a person checks before they reach the DB.

Why: separate URLs let Google show the right language to the right traveller, and sharing a link keeps its language.

D8 · One "Other services" page

The Services page already has one form with a picker for car, visa and flight, and it already asks the right questions. Keep it. Car rental's separate fleet page leaves the menu, and requests keep going to the existing insert-only enquiries table.

Why: the home page and tour browsing are what earn money. Services only need to be easy to request, not browsed like a catalogue.

D2 · One content layer, one tour shape

Every page reads through src/content. The Supabase public views are the source of truth; fixtures exist only for development and tests.

Why: three readers with three row shapes is how the tour page and the catalogue drift apart.

D3 · Design tokens before redesign

Move every colour, radius and type size into tokens first, then change the look by changing tokens.

Why: the new look becomes a small, reviewable diff instead of a rewrite of every page.

D4 · Contact, not checkout

Phase 1 ends at Zalo, phone, Messenger or the insert-only enquiry form. No price or seat is shown as confirmed.

Why: this matches how the agency sells today and the constitution's rule against implying confirmation. It also leaves the booking design open for phase 2.

D5 · Supabase Studio is the admin for now

Staff edit content in Studio. Publishing triggers a rebuild, either by hand or through a Supabase webhook that calls the deploy workflow.

Why: a custom admin is real work that belongs with the booking flow.

Refactor order

This morning: ship the visible UI

Only changes visitors can see, built on today's routing so nothing risky moves. Each item is tested on GitHub Pages, then you release it to the VPS yourself.

  1. Release setup. Switch "Deploy to VPS" to its manual button only, and write docs/RELEASING.md.
  2. Tokens and UI kit. Move inline colours into tokens. Extract Button, Section, Card and Accordion so the pages below share them.
  3. Tour detail redesign. Build the L4 layout: gallery, sticky tabs, itinerary, price, policy accordion, same-region tours, summary card, contact dock.
  4. Other services. Take Car rental out of the menu; car stays a choice on the existing Services form.
  5. Check and release. Type-check, build, review on GitHub Pages, then click Run on "Deploy to VPS".

Next: the structure underneath

  1. Content layer. Merge the three tour readers into src/content, with lang on every read. Commit or drop the untracked catalogue migration.
  2. Split the home page. Turn the 942-line file into features/home/*, and move its text into i18n/vi.ts.
  3. Routing and languages. Move to React Router 7 with real paths and /en/. Redirect old #/ links.
  4. Translate. Codex with gpt-6-luna at high effort translates the Vietnamese text into English files. A person checks them, then they load into the DB.
  5. Prerender. Build one page per tour, per language, with its own title and share image.
  6. Phase 2. Guest reviews, price packages, departure dates, booking with deposit, payment, custom admin.
