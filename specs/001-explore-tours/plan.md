# Implementation Plan: Explore Page (Tour Package Catalogue)

**Branch**: `001-explore-tours` | **Date**: 2026-08-05 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-explore-tours/spec.md`

## Summary

Add a second route to the currently single-page site: a catalogue of roughly 24 tour packages spanning 8 Vietnamese regions, with faceted filtering, diacritic-insensitive keyword search, sorting, and shareable filter URLs. Delivered client-side with a static typed dataset, a small hash router, and a pure filter engine, reusing the existing brand tokens without introducing a UI framework or backend.

## Technical Context

**Language/Version**: TypeScript 5.7, React 19

**Primary Dependencies**: React 19, Tailwind CSS v4 via `@tailwindcss/vite`, `@phosphor-icons/react` 2.1.10 (installed for this feature, replaces hand-rolled SVG icons). No router library, no state library, no animation library.

**Storage**: None. Catalogue is a static typed module compiled into the bundle.

**Testing**: No test runner is configured in this project. Verification is manual against the acceptance scenarios in spec.md, plus `tsc --noEmit` and a production build. Introducing a test runner is out of scope and noted as a follow-up.

**Target Platform**: Evergreen mobile and desktop browsers, deployed as a static site to GitHub Pages under a project subpath.

**Project Type**: Single-project frontend web application.

**Performance Goals**: Filter interaction under 100ms on mid-range mobile. CLS below 0.1. LCP below 2.5s on a 4G profile.

**Constraints**: Deployment sits on a GitHub Pages subpath, so routing MUST be hash-based to survive deep links without server rewrites. Bundle growth must stay modest; icons must be tree-shaken through named imports. No secrets, no network calls at runtime.

**Scale/Scope**: 2 routes, 8 regions, ~24 packages, 7 facet groups, roughly 12 new components across approximately 15 new files.

### Key technical decisions

1. **Hash routing, hand-rolled.** GitHub Pages serves no rewrites, so `#/explore` survives a deep link where `/explore` would 404. A `hashchange` listener with `useSyncExternalStore` is roughly 40 lines and avoids a router dependency.
2. **Filter state lives in the URL, not in component state.** The URL is the single source of truth, which satisfies FR-007 and makes browser history work without extra bookkeeping.
3. **Pure filter engine.** `filterTours` takes the dataset and filter state and returns results plus per-option counts in one pass, so the disabled facet counts in FR-010 cannot drift from the displayed results.
4. **No animation library.** `MOTION_INTENSITY` sits at 4, which is the CSS-transition band. Adding Motion for that would not be justified.
5. **Diacritic-insensitive search** via `String.normalize("NFD")` with combining marks stripped, plus explicit handling of `đ` which NFD does not decompose.
